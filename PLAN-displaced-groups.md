## 0. Goal, restated

A pick-one (or pick-many) group whose members sit at non-adjacent positions of one prompt order: the group row ("heading end") stays where it is with its adjacent members, and any number of further members elsewhere in the same sequence are **linked** to it. Compile, loadout layering, the ST-panel tick ("your tick wins"), the outline, undo and the MCP/REST ops all treat the linked members as ordinary group members; the prompt order never moves. Sola V3's two `[PICK 1: GROUNDING]` rows import as one linked group; the owner's FF CoT copies can be linked by hand (or by import note + one click). A deliberate, additive schema change with `upgradeDoc` tolerance, revision-restore compatibility and a live-library compile dry run proving zero change in sent text.

Out of scope (settled by the owner or by round 3, not reopened here): nested headings, the four selection rules, explicit section members, a heading that is a choice, "ignored and flagged" panel ticks (superseded by "your tick wins"), migrating the owner's live library (the session deploys), the markup spec itself (`docs/preset-markup.md` is a parallel draft; §1 says how it would encode links, nothing here depends on it).

## 1. Decisions on the open points

| Point | Decision | Rejected / why |

| **Where a linked group lives** | The existing **group row** is the heading end: `header` (or null) + adjacent `options` exactly as today, plus a new optional field **`remote: string[]`** — row keys (`leaf.key`, `newKey('row')` 4-byte hex, canonical.js:27 [read]) of block leaves elsewhere in the **same sequence**. Absent or `[]` = ordinary group; the field is written only when non-empty, so every existing document round-trips byte-identical. "Its members may also belong to an ordinary heading" holds for free: a remote leaf keeps its own rank (`item` at top level / inside a section, or `option` of another group) and position. | A doc-level `links` table keyed by block identifier: needs a brand-new render/op/validation path and an invented virtual heading, and one identifier appears in BOTH sequences (100000 and 100001, F-066), so identifier-keyed links are ambiguous per sequence. ## 4. What could go wrong, ranked (earliest visibility)
1. **Pruning post-pass alters an existing doc's rows** (e.g. it touches a field other than `remote`, or writes `remote: []`): chunk 1 (ii)/(viii) deepEqual on `remote`-less docs; the live dry run's `JSON.stringify` check is the canary.
2. **`seen` interaction** mis-implemented so a remote member escapes its rule (two members compiled on): chunk 1 (iv) and chunk 2's slot test; visible as a `converged()` mismatch in l2/l3.
3. **Lazy key index staleness**: `pickOneMembers` resolves keys against the doc at call time; an op that mutates `seq.rows` and then normalizes within the same call must resolve after the rebuild (createGroup/linkToGroup do dry rebuild → `refusePickOneConflict` on the NEW group — order matters). Visible in chunk 2 409 tests.
4. **F-066 dual sequences**: a recognizer that links in sequence 100001 must do the same in 100000 (same identifiers, different row keys); `remote` holds keys, so the two sequences carry different key lists. Visible in `browser-imports.test.js` validation of every fixture.
5. **Sortable/drag regressions** if a reference row lands inside `ul.pm-list`: `dragOps` would count it as a sibling and emit a wrong `moveLeaf` delta. Visible in l4 and `check-phase2 #14`.
6. **ST popup/UX**: the Make-group popup growing a sentence must not wrap the rank bar (round 3's `c5b79da` regression). Visible in `check-phase2`.
7. **Rollback**: a doc saved with `remote` loaded by 2.2.0 code validates and silently drops the links on its next save (old `rebuildSeq` has no `remote`). Documented in README "Update"; the library backup before deploy is the recovery.
8. **Nemo auto-link (Q3)** changes a fresh import's compile when 2+ members across runs are on in the file (the conflict note fires; bits are kept, compile keeps the last) — same practice as sola3. Visible in `nemo.test.js` with a synthetic two-run tag.
9. Known flakes: `check-fix1` f10, `check-nemo-delete` n4 — report, don't chase.
